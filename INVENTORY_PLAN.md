# План: Инвентарь, Кошелёк, Контейнеры и Торговцы (Фаза 2)

Статус: **план утверждён, реализация не начата.**
Источник правил: `_rules/15. Inventory.md`. Схемы: `DATA SCHEMA.md`. Баги API: `FOUNDRY V14 QUIRKS.md`.

## Утверждённые архитектурные решения

1. **Кошелёк — гибрид.** Список деноминаций задаётся в **настройках мира** (меню). На акторе кошелёк = числовые счётчики `system.currency.{key}` (хранится `ObjectField`, т.к. список валют динамический). Item-тип `currency` остаётся для «стопок монет» как лут, которые зачисляются в кошелёк при подборе.
2. **Контейнеры — актор + предмет-ссылка.** Контейнер (сумка/сундук/сумка удержания) — это актор типа `loot` в режиме `container`. На персонаже лежит предмет-ссылка (`flags.dedrel.linkedActorUuid`), выглядящий как обычный предмет; клик открывает лист контейнера.
3. **Транзакции — GM-брокер через socket (бесшовный).** Повторяем механику lootsheet: игрок НЕ владеет актором торговца/лута. Игрок эмитит socket-пакет активному ГМу на той же сцене (`processorId`), ГМ-клиент атомарно исполняет перемещение предметов и обмен валют. Без диалога подтверждения ГМа. Условие: ГМ онлайн и на той же сцене, взаимодействие через **токен на сцене**.
4. **Типы предметов — все сразу.** Добавляем `potion`, `scroll`, `craft_material`, `quest_item`; стандартизируем общие «физические» поля у всех предметов.
5. **socketlib разрешён.** Для брокера транзакций (Блок D) используем модуль `socketlib` (установлен) — чище, чем сырой `game.socket`. Держим число зависимостей минимальным.
6. **Таланты на грузоподъёмность.** В `bonuses-schema.mjs` добавить флаги: множитель/прибавка к порогам переноса и иммунитет к штрафам перегрузки. Учитываются в расчёте перегрузки (Блок B) с самого начала.

## Подтверждённая механика lootsheet (эталон для socket)

Файл-эталон: `/mnt/Data/FoundryVTT/Data/modules/lootsheet-simple/lootsheet-simple.js`.
- Игрок ищет ГМа: `u.isGM && u.active && u.viewedScene === game.user.viewedScene`.
- Пакет: `{ type: 'buy'|'loot'|'lootCoins'|..., buyerId/looterId, tokenId, itemId, quantity, processorId: gmId }`.
- Обработчик: `game.socket.on(SOCKET, data => { if (game.user.isGM && data.processorId === game.user.id) {...} })`.
- Покупатель = `game.user.character` (у игрока должен быть назначен персонаж). Продавец/контейнер = токен на канвасе.
- Если ГМ сам — сокет не нужен, вызываем транзакцию напрямую.

Отличия нашей реализации: собственный socket-канал `system.dedrel`; jQuery → нативный DOM (V14 QUIRK); `Dialog` → `DialogV2`.

## Блоки работ

### Блок E (делаем первым). Ревизия типов предметов и общих полей + миграция
Фундамент: экономика и вес зависят от единообразных полей.

- **Общий набор физических полей** (helper `physicalItemFields()` в новом `src/data/items/_physical.mjs`): `weight`, `base_price`, `rarity`, `quantity`, `stackable`, плюс где нужно `equipped`.
- **Привести к нему** `weapon`, `ammunition`, `magic_item` (сейчас нет части полей); согласовать `loot`, `trade_good`.
- **Новые data models + регистрация** (`index.mjs`, `system.json documentTypes.Item`, шаблоны `details-*.hbs`, lang): `potion`, `scroll`, `craft_material`, `quest_item`.
  - `potion`: `charges{value,max}`, `consumed_on_use`, `changes`, `formula_heal`, `requirements`.
  - `scroll`: `spell_id`, `charges`, `consumed_on_use`, `requirements`.
  - `craft_material`: `material_type`.
  - `quest_item`: `quest_id`, `can_be_sold=false`, `can_be_dropped=false`.
- **Миграция** (`src/migration.mjs`): проставить дефолты новых полей на предметах в компендиумах и на акторах; инициализировать `system.currency`, `system.resources.encumbrance`.
- Enum'ы: `ITEM_RARITY_ENUM`, `CURRENCY_DENOMINATION_ENUM` в `src/constants.mjs`.

### Блок A. Валюты и кошелёк
- **Data model актора**: `system.currency` = `ObjectField` (свободные ключи → count). Дериватив: `wallet_total_base`, `wallet_weight`.
- **Настройка мира — список валют**: `SettingsMenu` + `DialogV2`-форма. Структура элемента: `{ key, name, abbr, base_value, weight, color, icon }`. Хранится в `game.settings` (`scope: world`, JSON). Дефолтный набор: медь(1) / серебро(10) / золото(100) / платина(1000) с весами из правил.
- **Виджет кошелька** в шапке вкладки инвентаря: поле по каждой валюте (инлайн-редактирование), суммарная ценность в базовых единицах, кнопка «свернуть номинал» (auto-convert вверх).
- **Зачисление стопки-Item `currency`**: при подборе/использовании — прибавить `value` к соответствующему счётчику кошелька, удалить Item. (Плейсхолдер `exchange_rate_modifiers`/`properties` не трогаем — Фаза 3.)

### Блок B. Вес и перегрузка
- **Схема** в `character.mjs`: `resources.encumbrance {total, category, thresholds{light,medium,heavy}}`.
- **Расчёт** в `prepareDerivedData`: сумма веса физических предметов (× quantity) + вес кошелька + вклад контейнеров. Пороги `(STR+CON)*5/10/15`. Категория: light/medium/heavy/overloaded.
- **Штрафы** применяем по образцу существующего `armor_penalty` (правка `initiative`/`movement` + флаг для UI). Штраф «ко всем броскам» (−1/−3) — через `system.bonuses.global_*` (проверить существующий механизм в `bonuses-schema.mjs`), overloaded → `movement.max = 0`.
- **Индикатор-бар** перегрузки в шапке вкладки инвентаря (цвет по категории, отметки порогов).

### Блок F. Редизайн вкладки инвентаря
- Шапка: виджет кошелька + бар перегрузки.
- Секции с инлайн-контролами: количество (+/−), цена, редкость. Отдельная группа «Контейнеры» (клик → лист контейнера).
- Исключить `currency` из общего бакета (ветка `else` в `character-sheet.mjs`), т.к. появился кошелёк.
- Группировка новых типов (potion/scroll/craft_material/quest_item) в осмысленные секции.

### Блок D. Актор `loot` (Loot / Merchant / Container) + socket
- **Новый тип актора `loot`**: data model (`src/data/actors/loot.mjs`), регистрация (`ActorDataModels`, `system.json`, sheet, шаблоны, lang).
- **Режим** (`system.mode`): `loot` | `merchant` | `container`.
- **Экономика** (для merchant): `system.markup_buy` (наценка на покупку игроком), `system.markup_sell` (доля выкупа). Цена = `item.system.base_price × markup`. Пул валют торговца = такой же `system.currency`.
- **Упрощённый лист** (`src/sheets/loot-sheet.mjs`): список предметов с ценами, кошелёк, кнопки Купить/Продать/Забрать. Права: игрок с `limited`/`observer` видит лут-лист, GM — полный. **Время открытия/закрытия — НЕ реализуем.**
- **Socket** (`src/socket.mjs`): канал `system.dedrel`. Пакеты `buy`/`sell`/`loot`/`lootCoins`. GM-обработчик исполняет:
  - `buy`: проверить деньги покупателя → списать валюту у покупателя, начислить торговцу, переместить предмет.
  - `sell`: обратное, по `markup_sell`.
  - `loot`: свободный перенос предмета из контейнера покупателю.
  - Конвертация выручки: начислять в базовой деноминации, затем `свернуть номинал`.
- Инициализация сокета в `dedrel.mjs` (Hooks `ready`), выбор ГМа по образцу lootsheet.

### Блок C. Контейнеры (поверх Блока D)
- Контейнер = актор `loot` с `mode = container`.
- **Предмет-ссылка** на персонаже (тип `loot` или спец. `container`): `flags.dedrel.linkedActorUuid`, поле `weight_contribution`:
  - обычная сумка/сундук → собственный вес (или 0 на земле);
  - «сумка удержания» → фиксированный вес независимо от содержимого.
- Клик по предмету-ссылке → `linkedActor.sheet.render(true)`.
- Вклад в вес носителя учитывается в Блоке B через `weight_contribution`.
- **Тонкое место (решить при реализации):** удаление предмета-ссылки НЕ удаляет актор-контейнер — только предупреждение; перетаскивание предметов между листами через существующий `_onDrop` + socket при отсутствии прав.

## Порядок реализации
E → A → B → F → D → C.

### Решения по торговцам (Блок D)
1. Персональные скидки — **по игроку (User)**: `system.personal_discounts = { userId: %}`.
2. «Разделить деньги» — между **персонажами активных (онлайн, не-ГМ) игроков** (`user.character`).
3. Казна торговца — **ограничена кошельком** (`infinite_funds` по умолчанию false; при true скупка не лимитируется).
4. Услуга (`service`) — **оплата + карточка в чат** (+ применение Active Effects предмета покупателю), в инвентарь ничего не кладётся.

### Статус: Блок D (торговцы/лут/сундуки + service) — ГОТОВО (ждёт рантайм-проверки)
- Тип предмета `service` (`src/data/items/service.mjs`, партиал, регистрация, lang).
- Тип актора `loot` (`src/data/actors/loot.mjs`) с режимами loot/merchant/container; поля экономики + кошелёк + `loot_tables`.
- `src/utils/currency.mjs` — `DedrelCurrency`: walletBase, collapse, setWalletBase, buy/sellUnitPrice, format.
- `src/socket.mjs` расширен: `buy`/`sell`/`take`/`buyService`/`distributeCoins` (+ обратные `notify` инициатору). Все сделки ГМ-исполняемы.
- Лист `src/sheets/loot-sheet.mjs` + `templates/actor/loot-sheet.hbs`: конфиг ГМа (наценка/скупка/приём продажи/казна/перс.скидки по игрокам/таблицы + «Сгенерировать сток»), кошелёк, «Разделить деньги», сток с ценами и кнопками Купить/Забрать/Оплатить услугу; продажа — drag своего предмета на лист торговца.
- Регистрация актора+листа, TYPES.Actor.loot / TYPES.Item.service, полная локализация ru/en.
- **Требование сетапа:** игрокам нужен доступ **Observer** (Limited) к актору торговца/лута, чтобы открыть лист; изменения делает ГМ через socket.
- **Требует рантайм-проверки:** сделки (покупка/продажа/забор/услуга), лимит казны, «разделить деньги», генерация стока из RollTable (резолв результатов таблицы best-effort — возможна доводка под V14 API), продажа через drag.
- **Блок C (привязка контейнера к персонажу как предмет-ссылка, вклад в вес)** — ещё не сделан: сейчас сундук = отдельный актор loot (открывается напрямую). Линковка в инвентарь PC — следующий шаг.

### Статус: Блок B (вес/перегрузка) — ГОТОВО (ждёт рантайм-проверки)
- `bonuses-schema.mjs`: флаги талантов `carry_capacity_mult` (множитель порогов), `carry_capacity_flat` (плоская прибавка, кг), `ignore_encumbrance_penalty` (иммунитет к штрафам).
- `character.mjs` `prepareDerivedData`: суммарный вес (физ. предметы × количество + вес кошелька; currency-предметы не домножаются) → пороги `(STR+CON)·5/10/15` с учётом флагов → категория light/medium/heavy/overloaded. Штрафы (−1/−3 к `bonuses.global_roll`; −1м/полная остановка `movement.max`) применяются, если нет иммунитета. Ад-хок `this.resources.encumbrance` (как `this.wallet`), без схемы/миграции.
- Индикатор-бар перегрузки в шапке вкладки Инвентарь (цвет по категории, пороги, строка штрафа, значок иммунитета).

- **Смоук-тест:** набить инвентарь/кошелёк весом → проверить смену категории и бар; проверить, что при medium/heavy падают броски (global_roll) и скорость; талант с `carry_capacity_*`/`ignore_encumbrance_penalty` через Active Effect.
