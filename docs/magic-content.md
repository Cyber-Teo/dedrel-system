Модификаторы, состояния «Силы», таланты доступа, линейные доктрины с фиксированными
заклинаниями и пресозданные заклинания.

> `effect-keys.md` §3.7. Схемы данных: `data-schema.md`.

## 0. Как всё устроено (30 секунд)

```
src/config/magic.mjs (CONFIG.DEDREL.magic)   ← ВСЕ таблицы правил (единственный источник)
        ↓ читает
src/utils/spell-calculator.mjs               ← валидация лимитов + компиляция сборки
        ↓ используют
SpellConstructorApp (UI)  и  DedrelItem.use() (ре-валидация при касте)
        ↓ результат
Item типа "spell" — исходник сборки (chosen_*) + исполняемые поля (ap_cost, formula_damage...)
```

Правишь баланс → правишь `magic.mjs` и/или condition-предметы в компендиуме Conditions.

**После любых правок** `magic.mjs`: запусти макрос «Валидация магии»
(`macro for foundry/magic_validation_macro.js`) — ~40 эталонных сборок сверяют цены,
формулы Лестницы, владение доктринными модификаторами и формы.

## 1. Новая доктрина со свободной сборкой (как Материя)

Пример: добавляем Биомантию в Конструктор.

**Шаг 1. Конфиг** — `src/config/magic.mjs`, объект `doctrines`:

```javascript
new_doctrine: {
  label: "DEDREL.Magic.Doctrines.new_doctrine",
  baseDamageType: "necrotic",          // тип урона по умолчанию ("" = без типа)
  ladderShift: 1,                      // сдвиг ступени Лестницы урона (Пиро: +1)
  ignoresSource: true,                 // концепция Источника неприменима (Телекинез, Био):
                                       //   селект скрыт, move всегда доступна, 5-й ранг
                                       //   модификаторов гейтится Рангом Доктрины 5
  affinity:    [{ target: "tech:imbue", delta: -1 }],          // скидки
  restriction: [{ target: "mod:area_cone", delta: 1 },         // штрафы
                { target: "tech:create", forbidden: true }],   // полный запрет (mod и tech)
  caps: [{ target: "mod:duration", maxRank: 3 }],              // потолок ранга
  forms: ["bludgeoning"],              // доступные физические формы урона (Модификатор
                                       //   form; пустой список/нет поля = Форма недоступна)
  modifiers: ["knockdown"],            // доктринные Модификаторы, которыми доктрина владеет
  // Двухпутёвая доктрина? Добавь paths (см. hydromancy в конфиге). Путь может
  // переопределить forms целиком и ДОБАВИТЬ свои modifiers к списку доктрины:
  // paths: { path_a: { label, affinity, caps, forms, modifiers, special }, ... }
  unique: { /* маркеры уникальных свойств, см. ignite у пиромантии */ }
}
```

Синтаксис правил: `target` = `"tech:<ключ техники>"` | `"mod:<ключ модификатора>"`;
`delta` — сдвиг цены в ОД (итог клампится нулём); `forbidden: true` — недоступно;
`maxRank: N` / `allowedRanks: [..]` — ограничения ранга.

**Пути = купленные таланты** (реворк 2026-07, переключаемой «стойки» больше нет):
доступ к Пути открывает отдельный талант с AE
`system.doctrines.<доктрина>.paths.<путь>` | Override | `1` (ключи путей — в схеме
актора, `shared-schema.mjs → buildDoctrines`; новый путь = новый ключ в схеме).
Сборка «без пути» легальна всегда; при касте проверяется, что путь сборки изучен.

**Магический фокус (общее правило):** любое собранное заклинание требует
экипированного оружия с типом «магическое» — компилятор проставляет
`req_weapon_type.magic` автоматически, отдельно настраивать не нужно. Фокус даёт
бонусы к навыку «Магические атаки» через transfer-эффект на предмете-оружии
(`system.skills.magical_attacks.bonus | Add | N`) — эффект активен только пока
фокус экипирован (подавление ядром). У Пути Эха фокус — концептуально музыкальный
инструмент, но механически это то же magic-оружие, отдельной проверки нет.

**Шаг 2. Локали** — `lang/ru.json` + `lang/en.json` (ВСЕГДА оба):
- Название уже есть у всех 18 доктрин (`DEDREL.Magic.Doctrines.biomancy`).
- Для новых путей: `DEDREL.Magic.Paths.<ключ>`.

**Шаг 3. Талант доступа** — предмет talent в `packs/talents` с Active Effect
(2 change-строки, фаза apply проставится сама):

| Ключ | Режим | Значение |
|---|---|---|
| `system.doctrines.biomancy.unlocked` | Override | `1` |
| `system.doctrines.biomancy.rank` | Add | `1` |

Вторая строка — «подарочный» ранг 1 (обычный случай). Талант только на доступ —
без второй строки, первый ранг игрок купит за 2 XP на странице опыта.

**Шаг 4. Смоук-тест**: добавь кейс в `magic_validation_macro.js`, прогони.

Актор и страница опыта НЕ требуют правок: все 18 ключей доктрин уже в схеме,
доктрина появляется в Конструкторе автоматически по факту записи в конфиге,
а на странице опыта — по факту `unlocked`.

Уникальное свойство уровня «Поджигания» (кнопка наложения состояния у уронных
заклинаний) — это одна строка `unique: { ignite: "<ключ состояния>" }`: кнопку
рисует `postToChat` в `src/documents/item.mjs`. Свойство нового ТИПА (не сводится
к скидкам/капам/кнопке состояния) потребует кода — см. §7.

## 3. Новый Модификатор

1. `magic.mjs → modifiers`:

```javascript
penetration: {
  category: "complexity",              // scale | intensity | complexity (колонка UI)
  label: "DEDREL.Magic.Modifiers.penetration",
  // textRanks: true,                  // ячейки покажут текст подсказки вместо цены
  // exclusiveWith: ["..."],           // взаимоисключения
  // doctrinal: true,                  // ДОКТРИННЫЙ: виден/легален только владельцу
  //                                   //   (доктрина/путь объявляет ключ в modifiers: [...])
  // requiresTechnique: "imbue",       // легален только вместе с техникой (Насыщение)
  // requiresArea: true,               // требует Модификатора Области (Пыльная завеса)
  ranks: {
    1: { pierce: 1 },                  // «выхлоп» ранга — см. ниже
    2: { pierce: 2 }
    // отсутствующий ранг = недоступен (в UI будет прочерк)
  }
}
```

2. Локали: `DEDREL.Magic.Modifiers.penetration` + `DEDREL.Magic.RankHints.penetration.{1..5}` (ru+en).
3. **«Выхлоп»**: если ранги дают уже известные поля (`meters`/`lengthMeters`/`radiusMeters`,
   `targets`, `step` (ступень Лестницы урона), `heal`, `hp`, `rounds/special`, `attackBonus`,
   `saveDc/penalty/bonus/conditions` (+`durationMode`), `pushMeters`, `imbueValue`,
   `chain/reaction`, `hintFact: true` — строка RankHints в описание карточки) —
   компилятор подхватит их сам. НОВЫЙ тип выхлопа (как `pierce` в примере) требует
   ветки в `SpellCalculator.compile()` — что писать в `item.system`.
4. У доктринных модификаторов Сложность спасброска = 8 + 2 × ранг — прописывается
   в ранге явно (`saveDc`), компилятор берёт максимум по сборке.
5. Кейс в смоук-тест.

## 4. Состояния доктринных Модификаторов («Сила», «Сковывание», «Сбивание»...)

Источник истины — **компендиум Conditions** (предметы condition с заполненным
`system.key`). Конфиг хранит только ключи:

```javascript
power: { ranks: { 3: { saveDc: 14, conditions: ["disoriented", "blind", "fear"] }, ... } }
constrain: { ranks: { 3: { saveDc: 14, conditions: ["entangled"], durationMode: "rounds:1" } } }
```

У «Силы» выбор «штраф ИЛИ состояние» делает игрок селектом; у остальных
доктринных модификаторов состояния фиксированы рангом. Ключи `entangled`
(«Спутан») и `prone` («Сбит с ног») обязаны существовать в компендиуме —
если их ещё нет, создать (см. NOTES).

**Кураторский пул селекта — компендиум `magic_conditions`** (хотфикс 2026-07-16):
модификатор с `conditionsFromPack: "dedrel.magic_conditions"` строит список
состояний в селекте из предметов этого пака (добавил/убрал предмет — список
изменился, код не трогаем). Пак включён в CONDITION_PACKS (`dedrel.mjs`), так что
его условия работают при наложении; при пустом паке селект откатывается на
канонические массивы `conditions` ранга. Аналогично `optionsFromPack:
"dedrel.biomancy_adaptations"` у «Адаптации» — селект по именам предметов пака
(v1: выбор пишется текстом в карточку).

- Добавить состояние в выбор ранга: создай/найди condition в компендиуме → допиши
  ключ в массив `conditions` нужного ранга.
- Баланс самого состояния (эффекты, длительность) правится ТОЛЬКО в компендиуме —
  конструктор и кнопка «Наложить: X» берут актуальную версию через реестр статусов.
- Названия в UI приходят из имени предмета-условия, локали не нужны.

## 5. Линейные доктрины с фиксированными заклинаниями

Для доктрин без свободной сборки (Сущность/Беспредельное/Врождённая/Псионика),
где заклинания прописаны заранее. **Два пути:**

**Вариант А (рекомендуемый): spell-предмет без блока конструктора.**
Создай Item типа spell — его лист имеет полную вкладку Details (как у манёвра:
тип действия, ОД, формулы, спасбросок, цель/область, требования оружия) — и заполни
поля руками (`ap_cost`, `formula_attack/damage`, `save_*`, `template_*`, эффекты).
Поле `doctrine` оставь ПУСТЫМ — ре-валидация конструктора его пропустит, предмет
работает как обычная способность. Не забудь чекбокс «Магический фокус» в требованиях
оружия, если заклинание должно требовать фокус (Конструктор ставит его сам, руками — ты).
Плюс: тратит **ОД Магии** (+добор из универсальных) — правильный пул для заклинания.
Выдача: талант доктрины со списком в `adds_items` (предметы приедут на актора
автоматически, как у существующих талантов).

**Вариант Б: манёвр.** Годится, только если способность по духу боевой приём.
ВАЖНОЕ РАЗЛИЧИЕ: манёвры тратят **боевые ОД (ap_maneuver)**, а не ОД Магии —
для заклинаний это обычно неправильно. Используй Б осознанно.

**Вариант В: собрать конструктором в ГМ-режиме** (если заклинание выражается
компонентами Материи) и переименовать/дописать описание — получишь и правильные
поля, и ре-валидацию.

Ранги таких доктрин всё равно живут в `system.doctrines.<key>.rank` (страница опыта
работает из коробки), а заклинания гейтятся через `doctrine_rank_req`: с 2026-07
проверка ранга при касте работает и для доктрин ВНЕ конфига Конструктора (линейных) —
заполни у spell-предмета поля `doctrine` и `doctrine_rank_req`, остальная
ре-валидация сборки для них пропускается.

> **Фикс-заклинание у доктрины ИЗ Конструктора — ставь `is_fixed: true`** (с 2026-09-10).
> Автоматический пропуск ре-валидации срабатывает только у доктрин, которых нет
> в конфиге. Если доктрина в конфиге ЕСТЬ (Тенемантия, Биомантия), `#validateSpellCast`
> прогонит пустую сборку через калькулятор и завалит каст на `no_techniques`.
> Флаг `is_fixed` обрывает проверку сразу после гейта по Рангу. Он же — техническая
> основа **длинных кастов** (`_rules/16. Magic.md` §5.1): фикс-заклинание с `ap_cost: 0`,
> `uses_max: 1`, `uses_per: "long_rest"` и телесным компонентом в описании.
> Образец — `import_shadow_long_casts_macro.js`.

### 9.1 `ignoresSource` РЕАЛИЗОВАН (2026-07-16)

Флаг `ignoresSource: true` в конфиге доктрины работает: селект Источника скрыт,
`move` доступна всегда, 5-й ранг модификаторов гейтится Рангом Доктрины 5 через
обычный maxModCost (утверждённый вариант «б»). Использует Биомантия; для
Электромантии (когда разморозят) достаточно одной строки в конфиге. Телекинез
изъят из Конструктора 2026-07-16 (будет линейным, роадмап §3.1).

### 9.2 ~~Биомантия — модификатор Лечения~~ РЕАЛИЗОВАНО (2026-07-16)

Доктринный модификатор `heal` (владелец — Биомантия) компилируется в
`formula_heal` (кнопка «Исцелить» в карточке чата). Шкала — зеркало Лестницы:
2d4/2d6/2d8/3d6/3d8. `exclusiveWith: ["damage"]` (урон Биомантии и так запрещён).
Модификатор `adapt` (Адаптация) — ПЛЕЙСХОЛДЕР: v1 текстом в карточке, маппинг
«ранг → ключи мутаций» появится после вычитки базы мутаций (роадмап §3.3).

### 9.3 Тенемантия — переопределение Прочности и Формы (создание нежити)

Прочность и Форма у Тенемантии значат другое: не «стена с ХП», а «поднятая нежить»
(Прочность → ХП существа, Форма → тип/облик). Рекомендуемый механизм —
**пер-доктринные переопределения модификаторов**:

1. В конфиг доктрины добавить блок:
   ```javascript
   shadowmancy: {
     modifierOverrides: {
       durability: { label: "DEDREL.Magic.Modifiers.undead_hp", hints: "..." },
       form:       { label: "...", ranks: { /* свои выхлопы: тип нежити */ } }
     }
   }
   ```
2. Код: в `SpellConstructorApp._prepareContext()` и `SpellCalculator.compile()`
   мержить `modifierOverrides` доктрины поверх базового конфига модификатора
   (лейблы/подсказки — UI, выхлопы — компилятор).
3. Сам подъём нежити = спавн актора — упирается в отложенную механику «спавн
   создаваемых объектов» (NOTES.md); до неё нежить оформляется текстом в описании
   и токеном, который ГМ ставит вручную.

## 9.4 Адаптации против Насыщения — правило разделения (2026-09-11)

Оба модификатора умеют «улучшить тело», и без границы они конкурируют. Граница такая:

> **Насыщение выдаёт только числа** (+N к навыку или защите, DR N, +N урона оружию).
> **Адаптация выдаёт то, что числом не выражается:** бинарные способности, иммунитеты,
> новые чувства и режимы движения, ступени Лестницы, лечение за ход.

По числам Адаптация и так впереди — у неё своя длительность (Ранг Доктрины раундов),
Насыщению для того же нужна ещё и «Длительность», то есть +2 ОД. Опасность не в цене,
а в покрытии: Насыщение подходит к ЛЮБОМУ навыку и типу урона, а каталог адаптаций
конечен. Поэтому новые адаптации пишутся только в качественную зону — иначе каталог
превращается в худшую версию Насыщения.

По этому правилу нынешние девять делятся так: Кошачий глаз, Жабры, Звериное чутьё,
Когти и Регенерация — в своей зоне; три DR-черты и Гибкость дублируют Насыщение
(открытый вопрос в `BALANCE.md`, запись от 2026-09-10). Шесть черт, добавленных
2026-09-11 (Вторые веки, Нюх, Дыхательные мешки, Смещённые суставы, Выпуклые глаза,
Обратные колени), написаны строго качественными и Active Effects не несут:
