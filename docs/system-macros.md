# Реестр сложных механик системы Dedrel

Раньше в этом файле хранились макросы для реализации сложных механик. После внедрения
**DSL-модификаторов** (`flags.dedrel.mod`) и **шаблонных self-эффектов** (`@spentAp`)
большинство механик реализуются данными, без макросов. Полный справочник синтаксиса —
в `effect-keys.md` (разделы 2.2 и 2.3).

Здесь хранятся готовые рецепты: как пересоздать конкретные механики.

---

## Архитектура: три слоя

| Класс механики | Носитель | Пример |
|---|---|---|
| Отложенный бонус на будущий манёвр | DSL `flags.dedrel.mod` на эффекте технического состояния | Стрельба в движении |
| Мгновенный самобафф, в т.ч. от переменных ОД | Шаблонный эффект на предмете с `applyTo: "self"` и `@spentAp` | Вариативный блок |
| Уникальная логика (телепорт, спавн, опросы) | `on_use_macro` (аварийный люк) | редкая экзотика |

**Как манёвр вешает отложенный бонус при активации (основной путь):**
создайте Active Effect с DSL change-строкой прямо НА манёвре и включите ему режим
«на себя» (кнопка-человечка в строке эффекта). При использовании манёвра эффект
автоматически скопируется на владельца и будет сожжён движком в свой момент.
Отдельный Condition-предмет для этого не нужен.

**Когда нужен Condition-предмет:** если бафф должен накладываться вручную
(ГМом через HUD статусов) или несколькими разными манёврами из одного источника.
Тогда манёвр вешает его макросом-однострочником в `On Use Macro`:
`await actor.toggleStatusEffect("system_key_условия", { active: true });`
Id статуса = `system.key` условия; если key пуст — имя в нижнем регистре
с заменой не-буквенных символов на `_`.

## 1. Готовность к Рипосту (бесплатный манёвр ближнего боя)
**Где используется:** «Атака по возможности» и аналоги.
**Реализация:** техническое состояние «Готовность к Рипосту» с Active Effect:

| Параметр эффекта | Значение |
|---|---|
| Change-строка | ключ `flags.dedrel.mod`, значение `ap_set:0; filter:melee` |
| Duration | `rounds: 1` |
| Описание | «Ваш следующий манёвр ближнего боя не требует траты ОД.» |

Эффект сгорит при использовании подходящего манёвра или протухнет в конце хода.
Для точечного варианта (только Взмах/Удар/Выпад):
`ap_set:0; filter:key:maneuver_swing|key:maneuver_strike|key:maneuver_lunge`

## 2. Готовность к Выстрелу / Стрельба в движении (бесплатный дальнобойный манёвр)
**Реализация:** то же самое, фильтр `ranged`:

| Параметр эффекта | Значение |
|---|---|
| Change-строка | ключ `flags.dedrel.mod`, значение `ap_set:0; filter:ranged` |
| Duration | `rounds: 1` |

## 3. Прицеливание (Take Aim)
**Реализация:** техническое состояние «Прицеливание» с эффектом:

| Параметр эффекта | Значение |
|---|---|
| Change-строка | ключ `flags.dedrel.mod`, значение `attack:2; filter:ranged; consume:roll` |
| Duration | `rounds: 1` |

Бонус +2 добавится к следующему броску дальнобойной атаки и сгорит после броска.

## 4. Вариативный блок (Variable_Block) — переменная стоимость
**Требования:** у манёвра галочка `Variable Cost`, базовая и максимальная стоимость.
**Реализация:** Active Effect на самом манёвре (НЕ на состоянии):

| Параметр эффекта | Значение |
|---|---|
| Режим «на себя» | кнопка-человечек в строке эффекта (ставит `flags.dedrel.applyTo = "self"`) |
| Change-строка | ключ `system.defenses.block`, режим Add, значение `@spentAp` |
| Имя/описание | можно использовать плейсхолдер: «Блок +@spentAp» |
| Duration | `rounds: 1` |

При использовании манёвра система подставит фактически потраченные ОД вместо
`@spentAp` и применит эффект к владельцу. Доступны также `@apCost` (базовая
стоимость), `@overspent` (сверх базы) и арифметика: `@spentAp * 2`.

## Аварийный люк: on_use_macro

Для механик, которые не выражаются данными, у манёвров/талантов остаётся поле
`On Use Macro`. Система вызывает макрос с параметрами:

- `scope.actor` — актёр-владелец
- `scope.item` — сам предмет
- `scope.spentAp` — фактически потраченные ОД (для переменной стоимости)
- `scope.weapon` — оружие/щит, выбранные игроком в диалоге использования (или `null`, если манёвр не требует оружия)

Пример каркаса (V14: в change-полях используется `type`, а не устаревший `mode`):

```javascript
const effectData = {
    name: "Особый эффект",
    img: item.img,
    description: `Потрачено ОД: ${scope.spentAp}.`,
    changes: [{ key: "system.defenses.dodge", type: "add", value: String(scope.spentAp) }],
    duration: { rounds: 1 }
};
await actor.createEmbeddedDocuments("ActiveEffect", [effectData]);
```

Также доступны точки расширения (хуки):
- `dedrelPreUseItem` — `{actor, item, apCost}`; можно изменить `ctx.apCost` до диалога.
- `dedrelPreRoll` — `{actor, item, title, isSave, bonus, penalty, systemAttackBonus}`; можно изменить `ctx.bonus` / `ctx.systemAttackBonus`.

## 5. Поднять щит (переменный Блок + укрытие от типа щита)
**Механика:** трата 1-5 ОД → столько же к Блоку до следующего хода; дополнительно
Малое укрытие (средний щит) или Большое укрытие (ростовой щит).
**Реализация — комбинация двух слоёв:**

1. **Переменный Блок** — рецепт 4 (self-эффект `system.defenses.block` = `@spentAp`).
2. **Требование щита:** у манёвра включить `req_weapon_type.shield` — диалог
   использования сам предложит выбрать экипированный щит.
3. **Условия «Малое укрытие» и «Большое укрытие»** — обычные Condition-предметы
   в компендиуме условий (duration: до следующего хода). Их же можно вешать вручную через HUD.
4. **Выбор укрытия по щиту** — макрос в `On Use Macro` (у щитов должны быть
   заполнены `system.key`, например `shield_medium` / `shield_tower`):

```javascript
const shield = scope.weapon;
if (!shield) return;
const key = shield.system.key || "";
if (key === "shield_tower") {
    await actor.toggleStatusEffect("cover_large", { active: true });
} else if (key === "shield_medium") {
    await actor.toggleStatusEffect("cover_small", { active: true });
}
```

Id статуса = `system.key` условия (в примере — `cover_small` / `cover_large`);
если key у условия пуст — имя в нижнем регистре с заменой не-буквенных символов на `_`.

## 6. Темп оружия: «Быстрое» и «Медленное» (движок, не данные)

**Где используется:** атакующие реакции — Рипост, Карающий промах, Атака по
возможности, Упреждающий укол (`maneuver_riposte`, `maneuver_punishing_miss`,
`maneuver_attack_of_opportunity`, `maneuver_preemptive_thrust`).

**Почему не DSL.** Это не отложенный бафф, а постоянное свойство железа в руках,
и величина зависит от того, каким именно оружием проводится реакция. Эффектом на
предмете это выражалось бы плохо: перенос (`transfer`) не смотрит на `equipped`,
и скидка работала бы из мешка. Поэтому механика живёт в коде:

| Что | Где |
|---|---|
| Список манёвров под темп | `src/utils/dedrel-bonuses.mjs`, const `TEMPO_MANEUVERS` |
| Расчёт сдвига | `DedrelBonuses.applyWeaponTempo(apCost, item, weapon)` |
| Цена в диалоге (по первому валидному оружию) | `src/documents/item.mjs`, `use()` |
| Фактическая цена (по выбранному оружию) | `item.mjs`, `#confirmUse()` |
| Подпись темпа в списке оружия | `item.mjs`, `#buildUseDialogContent()` |

**Правила:** «Быстрое» −1 ОД, «Медленное» +1 ОД, пока оружие экипировано
(13. Weapons §Свойства). Нулевую цену темп не двигает: манёвр, сделанный
бесплатным баффом (`ap_set:0`), Медленное оружие обратно не удорожает.

**Как добавить оружию темп:** флаги `system.is_fast` / `system.is_slow` на самом
оружии, ничего больше. Новый манёвр под темп — дописать его ключ в
`TEMPO_MANEUVERS`.
